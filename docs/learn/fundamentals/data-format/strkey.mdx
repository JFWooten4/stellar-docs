A StrKey (string key) is Stellar's human-readable encoding for a typed binary identifier. Despite the name, not every StrKey represents a cryptographic key: contract IDs, liquidity pool IDs, and claimable balance IDs also use this format.

## Encoding

A StrKey [encodes](https://github.com/stellar/rs-stellar-strkey/blob/0f133c3c87dccc0e6a8e67182230658970f7d660/src/convert.rs#L62-L75) the following byte sequence using uppercase Base32 without padding:

```text
version byte || payload || CRC16-XModem checksum
```

The two-byte checksum is calculated over the version byte and payload and stored in little-endian order. The version byte identifies the payload type. Its high five bits become the first Base32 symbol, producing the recognizable prefix; the low three bits are zero in every currently assigned version byte. For example, the `M` version is `0x60`, or `01100000` in binary, so its first five bits are `01100`, the Base32 value for `M`.

The [canonical version-byte assignments](https://github.com/stellar/rs-stellar-strkey/blob/0f133c3c87dccc0e6a8e67182230658970f7d660/src/typ.rs) and [reference encoders](https://github.com/stellar/rs-stellar-strkey/tree/0f133c3c87dccc0e6a8e67182230658970f7d660/src) define these decoded payloads:

| Prefix | Leading bits | Version byte | Identifier | Decoded StrKey payload |
| --- | --- | --- | --- | --- |
| `G` | `00110` | `0x30` | Ed25519 public key (account ID) | 32-byte Ed25519 public key |
| `S` | `10010` | `0x90` | Ed25519 secret seed | 32-byte Ed25519 seed |
| `M` | `01100` | `0x60` | Muxed account | 32-byte Ed25519 public key + big-endian `uint64` ID |
| `T` | `10011` | `0x98` | Pre-authorized transaction signer | 32-byte transaction-signature-payload hash |
| `X` | `10111` | `0xb8` | Hash-X signer | 32-byte SHA-256 hash of the signer's preimage |
| `P` | `01111` | `0x78` | Ed25519 signed-payload signer | 32-byte public key + XDR variable opaque payload (1–64 bytes) |
| `C` | `00010` | `0x10` | Contract ID | 32-byte contract ID hash |
| `L` | `01011` | `0x58` | Liquidity pool ID | 32-byte liquidity pool ID hash |
| `B` | `00001` | `0x08` | Claimable balance ID | One-byte balance-ID type (`00` for V0) + 32-byte balance hash |

These rows describe the bytes inside the StrKey envelope, which are not always a byte-for-byte copy of the corresponding XDR object. The protocol's [`AccountID`, signer keys, `ContractID`, `PoolID`, and `ClaimableBalanceID`](https://github.com/stellar/stellar-xdr/blob/70180d5e8d9caee9e8645ed8a38c36a8cf403cd9/Stellar-types.x) are discriminated unions or aliases. An `M...` payload follows the layout defined by [SEP-23](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0023.md#specification): the public key followed by the 64-bit multiplexing ID, although the corresponding [XDR `MuxedAccount`](https://github.com/stellar/stellar-xdr/blob/70180d5e8d9caee9e8645ed8a38c36a8cf403cd9/Stellar-transaction.x#L21-L34) struct lists the ID first. A `P...` payload uses the signed-payload signer's XDR representation, including its four-byte big-endian length and zero padding to a four-byte boundary, so its total decoded payload length is 40–100 bytes.

The prefix alone does not make a StrKey valid. A decoder must also verify the Base32 encoding, version byte, payload length, and checksum. The checksum detects accidental corruption; it does not authenticate the value. Treat `S...` secret-seed StrKeys as credentials and never expose them.

Use a Stellar SDK or the [`stellar-strkey` reference implementation](https://docs.rs/stellar-strkey) to encode and validate StrKeys instead of implementing the format manually.

## Claimable balance IDs

A V0 claimable balance payload contains a one-byte `00` discriminant followed by its 32-byte hash, so its `B...` StrKey is 58 characters long. The same logical ID encoded as XDR hex uses the four-byte `00000000` union discriminant followed by the hash, producing 72 hexadecimal characters. Check which representation an API or SDK expects before passing the ID.

For example, the Python SDK [encodes and decodes](https://github.com/StellarCN/py-stellar-base/blob/96c1910a84ffe1ae926b8dc77daee9c3e8afa937/tests/test_strkey.py#L326-L344) the payload `003f0c34bf93ad0d9971d04ccc90f705511c838aad9734a4a2fb0d7a03fc7fe89a` as:

```text
BAAD6DBUX6J22DMZOHIEZTEQ64CVCHEDRKWZONFEUL5Q26QD7R76RGR4TU
```
